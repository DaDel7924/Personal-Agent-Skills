# 核对方法论

目标不是"证明我算对了"，而是**构造一个会失败的机会**。同源核对（用生成阶段的数据文件去核对生成结果）永远通过，等于没做。

## 三条铁律

1. **不同源**：核对脚本只读原始成绩包与成品文件，不读中间 JSON。
2. **单元格级**：比到格子，不比"总数对得上"。
3. **全量重跑**：任何数据变更后跑全量，不做增量。单轮 1.1 万项的成本远低于漏一处的代价。

## 分层核对

| 层 | 对象 | 方法 |
|---|---|---|
| L1 源表复算 | 指标表本身（联考） / 内部恒等式（单校） | 联考：由学生榜重算校均分，与"整体"行比对；逐校合并重排名次验证名次列。单校：走 `exam-mode.md` 五节的六条恒等式 |
| L2 成品数值 | Excel / PPT 每个数值格 | 由原始数据按锁定口径重算，与成品单元格比对，容差 0.005 |
| L3 成品分类 | "是/否"、`n/有效`、名次 | 按格式化后字符串精确比 |
| L4 成品文字 | 每句结论的关键量 | 抽取数字复算：分差、占比、人数、班级数、档位人数 |
| L5 结构 | 图表、筛选、冻结窗格、合并单元格 | 改写前后 zip 条目比对 + 功能项断言 |

L4 是唯一能抓住"事实性表述错误"的层次，不能省。真实案例中 L2/L3 全部 0 错，L4 抓出 4 处硬错：
"13 个班全部高于 10 月"（实为 12）、"物理贡献率最低"（实为第 6）、"320 班最低"（实为 322 班）、"7 个班/9 人/3 人"（实为 6/10/5）。

## 容差与白名单

三类差异**不是错误**，必须单列，否则报告会被假报警淹没：

1. **同分并列行序**：名次相同、顺序不同。按"名次+姓名"匹配，或单列统计。
2. **`x.xx5` 边界**：0.01 差。单列为"精度备注"。
3. **显示值 vs 原值相减**：如超均率按显示值算 −17.58、按原值算 −17.59。取源表原值口径，并在备注说明。

白名单必须**逐项写清理由**，不能笼统"已知差异忽略"。

## 报告格式

```
合计 <N> 项核对
- 不符：<n> 项（逐条：文件/位置/现值/复算值/差异原因）
- 精度备注：<n> 条（非错误，说明口径）
- 白名单：<n> 条（同分并列等，附理由）
```

结论只有三种：`全部通过` / `存在 n 项待修` / `存在 n 项需用户裁决`。禁止输出"基本正确"。

## 核对失败时的处理顺序

1. 先判断是**成品错**还是**口径理解错**。查 Phase 0 口径表。
2. 若为口径分歧 → 提交用户裁决，不自行修改。
3. 若为成品错 → 定位到最小改动集，备份 → 改 → 重跑核对 → 与备份逐格 diff，证明只改了预期格子。
4. 记录到 run-log，写清"错在哪、为什么没早发现、加了什么检查防复发"。

## 单校模式：没有外部锚点怎么办

联考模式可以用 N 校指标表与一分一段表交叉验证，单校模式没有。此时核对对象变成**内部恒等式**，六条必须全过：人数闭合、总分闭合、加权闭合、排名闭合、环比闭合、赋分闭合（逐条见 `exam-mode.md` 第五节）。

风险提示：单校模式的错误不会被外部数据"撞出来"，只能靠恒等式。恒等式全过仍可能有口径错误（比如把赋分当卷面），所以口径页必须写清每列的量纲。

## 常见核对盲区

- 只核数值不核**单位与量纲**（赋分差当原始分差）。
- 只核表格不核**副标题与脚注**（"自主划线"这类措辞在划线性质变更后必须同步）。
- 只核当前版本不核**旧值残留**（作废的分数线、旧人数会散落在说明页、索引页、筛选区）。
- 只核主表不核**筛选区范围**（新增行后自动筛选仍只到旧行号，末尾数据被隐藏）。
- 只核文件不核**跨文件一致性**（同一分数线在 3 份 Excel + 30 页 PPT 中必须完全一致）。

## 复核规模参考

| 对象 | 项数级 |
|---|---|
| 校际汇总簿（20 校以上 × 9 科） | ~200 |
| 班级分析簿（13 班 × 3 次 × 9 科 + 教师 + 前 N + 上线） | ~2000 |
| 学生分层簿（200 人 × 12 列） | ~6000 |
| PPT（30 页数值格） | ~1400 |
| 短板诊断页 | ~100 |

四项合计约 1.1 万项，脚本单次运行约 10–30 秒。任何一次"改动很小应该没问题"的侥幸，都比这个成本高。

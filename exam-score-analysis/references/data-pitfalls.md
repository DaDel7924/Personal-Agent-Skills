# 数据陷阱库

每条格式：**现象 → 判别 → 处理**。全部来自真实项目事故，按踩坑概率排序。

---

## 1. 扩展名 .xlsx，实为 OLE2 老式 .xls

**现象**：`openpyxl.load_workbook()` 抛 `zipfile.BadZipFile: File is not a zip file`。

**判别**：`file xxx.xlsx` 显示 `Composite Document File V2 Document` 而非 `Microsoft Excel 2007+`。

**处理**：改用 `xlrd.open_workbook()`。封装成 try/except 回退（见 `scripts/reader.py: read_any`）。不要试图改名或转码，直接双路径读取最稳。

---

## 2. 有效样本过滤条件选错，人数虚增

**现象**：某班 18 人，系统统计 17 人；按"总分非空"过滤得 18 人。

**判别**：`分数段分布/一分一段` 的累计人数与"整体排名"列存在 9–26 人系统偏移。

**处理**：**以"整体排名为数字"作为参与统计的判据**，不用"总分非空"。缺考生的总分列常写占位 `0`、排名列写 `-`，只看总分会把缺考当 0 分纳入，拉低均分。学生榜另有"是否参与统计"列时优先用该列。

---

## 3. 再选科目实为赋分，被当卷面分解读

**现象**：化学均分 58.70、物理均分 24.55，看似化学远好于物理，实为量纲不同。

**判别**：看**最低分**。统计全部参评校（N 所；单校考试则统计全校各班）该科最低分，若无一低于 30 且多校/多班恰为 30（赋分起点），即为赋分；对照首选科目最低分可低至个位数（物理 3、历史 11）即为原始分。另一个判据：赋分科目全校均分集中在 55–65 区间。

**处理**：跨校对比只能用赋分；环比改用卷面（数据包若只有赋分，必须明确声明"本校环比在赋分口径下进行，幅度受赋分基数影响"）。报告里"分差"与"赋分差"、"得分率"与"赋分得分率"要分名。赋分四科的"得分率"若按满分 100 计，有效区间只有 30–100（70 分），可另给"按有效区间折算"的比率。

---

## 4. 指标表各科人数 ≠ 总分人数

**现象**：总分 8265 人，语文 8263 人。

**判别**：读"整体"行的人数列，逐科比对。

**处理**：合并基准必须**逐科按该科实际人数加权**，不能用总分人数。合并后的基准是自算值，须在口径页声明"非表内原值"。

---

## 5. 汇总行混入班级聚合

**现象**：13 个班的均分平均后与"年级"行不符。

**判别**：班级对比表末尾存在"年级""整体""合计"行。

**处理**：按班级聚合前先剔除这些行。判据：班级列不是纯数字/不是 `3xx` 格式即剔除。

---

## 6. ROUND_HALF_UP 与银行家舍入差 0.01

**现象**：脚本算 21.625 → 21.62，教务系统显示 21.63。

**判别**：精确均值恰为 `x.xx5`。

**处理**：全程用 `float(Decimal(str(x)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))`。核对时容差取 0.005，并把 `x.xx5` 边界单独列为"精度备注"而非错误。

---

## 7. 同分并列导致行序不一致

**现象**：两名学生总分相同（如 423.5），逐生比对时行序相反，触发大量假报警。

**判别**：名次列数值相同。

**处理**：核对时按"名次 + 姓名"双键匹配，或在报告中把并列行序差异归入白名单单独统计，不计入不符项。

---

## 8. 一分一段累计人数与排名列偏移

**现象**：某分数在一分一段表对应第 5372 名，学生榜该生排名 5381。

**判别**：偏移量在 10–30 人内且方向一致。

**处理**：偏移源自一分一段含未参与排名者。以一分一段定分数线（权威），用学生榜验证上线人数，两者一致即通过。报告里注明偏移存在，不要强行对齐。

---

## 9. openpyxl 重存丢图表 / 条件格式

**现象**：改写一个单元格后，原表的柱状图消失、色阶失效。

**判别**：原 xlsx 含 `xl/charts/chart1.xml`、`xl/drawings/drawing1.xml`。

**处理**：不要 `load_workbook` + `save`。改用 zip 直改写：解包 → 只替换目标 `sheet*.xml` 里的目标单元格 → 其余条目按原 `date_time`/`compress_type` 逐字节复制 → 重新打包。事后核对 zip 条目数不变、chart xml 仍在。见 `scripts/xlsx_patch.py`。

若必须用 openpyxl 重建图表：`ConditionalFormattingList` 无 `remove` 方法，需整体重置；合并单元格要先 `unmerge` 再写。

---

## 10. 中文存为数字字符实体，替换失败

**现象**：在 sheet xml 里搜"171名"搜不到。

**判别**：该表用 inlineStr、无 `xl/sharedStrings.xml`，中文以 `&#NNNN;` 形式出现。

**处理**：解码 → 与旧文精确比对 → 重新实体编码后写回。替换前必须确认**唯一命中**，命中 0 次或多次都直接报错退出，禁止盲改。

---

## 11. python-pptx 改文本后整段不显示

**现象**：写入了文字，PowerPoint 打开该段空白。

**判别**：用 lxml 把 `<a:r>` append 到段落末尾。

**处理**：DrawingML 要求 `<a:r>` 出现在 `<a:endParaRPr>` 之前。必须 `paragraph.add_run()` 再替换该 run 的 `rPr`，让库负责顺序。改完用 python-pptx 回读断言文本存在。

---

## 12. 子代理报告"已写入"，文件实为空壳

**现象**：子代理返回完整数值与"10 个 sheet 已写入"，磁盘文件 4.8KB。

**判别**：`ls -l` 体积异常小；`load_workbook` 后 `sheetnames` 数量不足。

**处理**：**凡委派子代理写文件，必须回读磁盘校验**（体积 + 工作表数 + 抽查 2–3 个单元格）。不采信自述。校验失败即在主机侧重做。

---

## 附：数据源版本漂移

同一天内工作簿可能被重生成多次。防御三件套：

1. 记录**结构指纹**（表名列表 + 每表列名序列 + 有效行数 + 文件 sha256 前 8 位）；
2. 用**列名**定位，不用列序号（真实案例：单科表由 12–15 列扩到 14–17 列，列序号全错位）；
3. 每次重生成后先跑"新旧提取结果逐字段 diff"，确认数值是否真的变了，再决定重做范围。真实案例中 V2.3 适配新版工作簿时，结构大变但**数值零变化**，只改了提取脚本。
